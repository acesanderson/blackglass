# Blackglass

Blackglass is an HTTP API server and companion command-line interface (CLI) client designed for programmatically managing, searching, and synchronizing Obsidian markdown vaults. It turns a local directory of markdown files into a structured, queryable data store featuring full-text, semantic, and hybrid search.

## Overview

The system consists of three primary components:

* **FastAPI Server (`blackglass-server`)**: Exposes endpoints for note CRUD operations, frontmatter modification, path refactoring (with wikilink rewriting), and multiple search modalities.
* **CLI Client (`blackglass-client`)**: Provides terminal-based administrative control over the vault.
* **Vector Indexer**: Utilizes a PostgreSQL database with the `pgvector` extension to store and query document embeddings generated by an external embedding service.

```
                  ┌───────────────────┐
                  │ blackglass-client │
                  └─────────┬─────────┘
                            │ (HTTP API)
                            ▼
                  ┌───────────────────┐      Git Sync
                  │ blackglass-server ├───────────────► [ Git Remote ]
                  └────┬──────────┬───┘
                       │          │
                       │          ▼
                       │    ┌─────────────────────────┐
                       │    │ Obsidian Vault Directory│ (.md files)
                       │    └─────────────────────────┘
                       ▼
       ┌──────────────────────────────┐
       │   PostgreSQL (pgvector)      │
       │  - Document Embeddings       │
       └──────────────────────────────┘
```

## Key Features

* **Multi-Modal Search**: Offers standard full-text search, semantic vector search, and hybrid search using Reciprocal Rank Fusion (RRF).
* **Git Synchronization**: Triggers remote pulls and performs incremental re-indexing of modified files using SHA-256 hashes.
* **Link Refactoring**: When a note is moved, the server scans the entire vault and automatically updates matching internal wikilinks (`[[Note Name]]`).
* **Frontmatter Management**: Structured reading and writing of YAML frontmatter without destroying the markdown document structure.
* **Periodic Notes**: Built-in support for resolving, creating, and modifying daily notes based on configurable time zones.

## Installation & Setup

### Prerequisites

* Python 3.12 or newer
* PostgreSQL database with the `pgvector` extension installed
* An instance of a Nomic-compatible embedding server (configured via `BLACKGLASS_BACKWATER_URL`)
* A Git-initialized directory containing markdown notes (the Obsidian vault)

### Server Installation

1. Clone the repository and navigate to the server directory:
   ```bash
   cd blackglass-server
   ```

2. Install the package:
   ```bash
   pip install .
   ```

3. Set up the required environment variables:
   ```bash
   export BLACKGLASS_VAULT_PATH="/path/to/your/obsidian/vault"
   export BLACKGLASS_API_KEY="your-secure-api-key"
   export POSTGRES_PASSWORD="your-database-password"
   export POSTGRES_USERNAME="your-database-username" # Defaults to 'bianders' if unset
   export BLACKGLASS_BACKWATER_URL="http://localhost:8080"
   ```

4. Launch the server using Uvicorn:
   ```bash
   python -m uvicorn blackglass_server.main:app --host 0.0.0.0 --port 8083
   ```

### Client Installation

1. Navigate to the client directory:
   ```bash
   cd ../blackglass-client
   ```

2. Install the CLI client:
   ```bash
   pip install .
   ```

3. Configure the environment variables for the client connection:
   ```bash
   export BLACKGLASS_URL="http://localhost:8083"
   export BLACKGLASS_API_KEY="your-secure-api-key"
   ```

## Quick Start

Verify the installation and perform core tasks using the CLI client.

### 1. Perform Git Sync and Update Embeddings
Sync the local vault folder with the Git remote, scan for changes, and update the PostgreSQL vector database:
```bash
blackglass vault sync
```
*Expected Output:*
```
git: Already up to date.
checked: 142  indexed: 0
```

### 2. Search Your Vault Semantically
Query the vault using conceptual/semantic meanings rather than exact keyword matches:
```bash
blackglass search semantic "optimizing database performance" --limit 2
```
*Expected Output:*
```
  Engineering/Postgres_Optimization.md
    score: 0.892
  Reference/Database_Indexing.md
    score: 0.841
```

### 3. Append to a Daily Note
Append an entry to today's periodic daily note (the file is automatically created if it does not exist):
```bash
blackglass notes append "periodic/today" "## 14:00 - Database index maintenance completed."
```

## CLI Reference

The `blackglass` command-line utility is structured into three command groups:

### `notes` (Note CRUD & Modification)

| Command | Arguments / Options | Description |
| :--- | :--- | :--- |
| `get` | `<path>` | Retrieve a note's raw contents and metadata. Use `--json` for raw output. |
| `create` | `<path> --content "<text>"` | Create a new markdown note. |
| `update` | `<path> --content "<text>"` | Overwrite an existing note's body. |
| `append` | `<path> "<text>"` | Append text to the end of a note. |
| `set-frontmatter` | `<path> <key> <value>` | Add or update a metadata value in the YAML frontmatter. |
| `delete` | `<path>` | Delete a note from the vault. |

### `vault` (Vault Utilities)

| Command | Arguments / Options | Description |
| :--- | :--- | :--- |
| `files` | None | List all markdown files in the vault. |
| `tags` | None | List all tags found across frontmatter blocks, including counts. |
| `periodic` | None | List all daily/periodic notes sorted chronologically. |
| `backlinks` | `<path>` | Find all notes containing wikilinks that target `<path>`. |
| `sync` | None | Trigger a Git pull and run incremental embedding updates. |

### `search` (Search Operations)

| Command | Arguments / Options | Description |
| :--- | :--- | :--- |
| `text` | `<query>` | Run a case-insensitive full-text search. |
| `semantic` | `<query> [--limit <n>]` | Run a vector search on indexed note embeddings. |

## HTTP API Reference

For integration with programmatic workflows or external agents, the server exposes the following REST endpoints. All requests must include the `X-API-Key` header.

### Notes API

* `GET /vault/notes/{path}` - Returns note body, parsed frontmatter, wikilinks, and tags.
* `POST /vault/notes?path={path}` - Creates a new note. Fails with `409 Conflict` if the file exists.
* `PUT /vault/notes/{path}` - Replaces entire note content.
* `PATCH /vault/notes/{path}` - Performs targeted operations based on the body payload:
  * `append`: Appends content to the note.
  * `prepend`: Prepends content (beneath the frontmatter if present).
  * `set_frontmatter`: Modifies or adds a specific frontmatter key/value.
  * `replace`: Performs precise anchor-based search-and-replace.
* `POST /vault/notes/batch` - Reads up to 50 files in a single network round-trip.
* `POST /vault/notes/{path}/move` - Moves a note. If `rewrite_links` is true, automatically rewrites references pointing to this note across the entire vault.

### Search API

* `GET /vault/search?q={query}` - Returns full-text search matches with highlighted excerpts.
* `GET /vault/semantic-search?q={query}&limit={limit}` - Returns vector similarity results.
* `GET /vault/hybrid-search?q={query}&limit={limit}` - Combines text and semantic search rankings using a Reciprocal Rank Fusion (RRF) algorithm.

### Vault Utility API

* `GET /vault/files` - Lists all notes, supports filtering by frontmatter values (`?fm.status=active`), tags (`?tag=work`), and path patterns (`?path_glob=Projects/*.md`).
* `GET /vault/changes?days={n}` - Parses Git revision history to return flat lists of created, modified, or deleted files.

## Automated Syncing via Cron

The repository contains a helper job script (`jobs/sync_vault.py`) that can be integrated with scheduler daemons like Cron or Cronicle.

To execute the sync script:

```bash
uv run --with httpx jobs/sync_vault.py --cron
```

The script performs a health check on the `/health` endpoint prior to triggering the sync API. If the server is offline or unreachable, the script logs the warning and exits cleanly with status `0` to avoid triggering false alarms in scheduling systems. Ensure `BLACKGLASS_URL` and `BLACKGLASS_API_KEY` are populated in the executing environment.
